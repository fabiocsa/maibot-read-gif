# 动图帧识别（Read Animation）

让麦麦真正"看见"群里的 GIF / 动态表情。

MaiBot 的视觉链路在把图片交给模型前会把动图**压成首帧**，模型只能看到一张静止画面。
本插件在消息进入主链之前拦截：解码全部帧 → 按时间等间隔抽帧 → 拼成一张带帧号/起始时间/持续时长的帧板 → 调用宿主视觉模型生成描述 → 把描述以文本形式插回消息。这样规划/回复模型就能理解动图里的动作、变化和梗。

思路参考 [dsh-read-animation](https://github.com/NeoHotaru/dsh-read-animation)，按 MaiBot 插件机制重写。

## 特性

- 支持 **GIF / 动画 WebP / APNG**，静态图自动跳过；
- 帧板带帧号与时间标注，并附总帧数、时长、帧率、循环信息；
- 使用宿主已有的 `vlm` 模型任务，插件本身不内置任何模型/密钥；
- 描述缓存：同一张动图第二次出现直接命中，不再调用视觉模型；
- 每条消息识别上限、触发范围、并发上限可配；
- 视觉模型失败/超时自动降级为"只注入元信息"，不影响正常聊天；
- 保留原始图片组件不动，宿主图片库、WebUI 聊天记录与原有图片描述流程不受影响。

## 安装

1. 把本目录放进 MaiBot 的 `plugins/` 下（目录名 `maibot-read-animation`）；
2. 重启 MaiBot（或在 WebUI 插件管理中加载）；
3. 首次加载会在插件目录生成 `config.toml`，按需修改。

依赖 `Pillow`（MaiBot 主程序本身已依赖，无需额外安装）。

## 配置

插件通过 `config_model` 自动生成 `config.toml`，主要配置节：

| 配置节 | 说明 |
| --- | --- |
| `[plugin]` | `enabled` 开关、`config_version` |
| `[trigger]` | 处理图片/表情动图、触发范围（`all` / `mentioned` / `off`）、每条消息识别上限 |
| `[frames]` | 最大抽帧数、单帧长边、帧板列数、透明通道处理、输入体积/帧数/时长上限 |
| `[vlm]` | 视觉任务名（默认 `vlm`）、可选具体模型、温度、最大输出、超时、描述最大字数 |
| `[inject]` | 注入前缀（默认 `[动图]`）、是否附带元信息与采样提示 |
| `[cache]` | 缓存开关、最大条目、保留天数 |
| `[perf]` | 视觉识别并发上限 |

> 视觉能力依赖主程序 `model_config.toml` 中 `model_task_config.vlm` 已配置可用模型（且模型支持图片输入）。

## 工作方式

```
入站消息
  └─ Hook chat.receive.before_process（阻塞、优先执行）
       ├─ 快速检查是否含 image/emoji 二进制
       ├─ 魔数嗅探 GIF / WebP(ANIM) / APNG(acTL)
       ├─ 缓存命中？→ 直接注入缓存描述
       ├─ Pillow 解码：帧数、总时长、fps、循环
       ├─ 等间隔抽帧 → 带标注帧板（JPEG/PNG）
       ├─ ctx.llm.generate(task_name="vlm", 帧板图片)
       └─ 原组件后插入 text 组件：[动图] GIF 480x270 · 24帧 · 1.2s · 约20fps · 循环；画面：……
```

注入示例：

```
[动图] GIF 480x270 · 24帧 · 1.2s · 约20fps · 循环；画面：一只橘猫趴在键盘上，前几帧缓缓抬头，随后突然弹起扑向镜头，画面晃动后落地；整体是搞怪表情包风格；（基于等间隔采样帧生成，帧间细节可能有遗漏）
```

## 限制

- 不支持视频（MP4/WebM），这类消息保持原样；
- 单条消息整体 Base64 体积过大时（>16MB RPC 帧上限），Hook 载荷本身会超限，插件只能跳过；
- 入站图片若被主程序的"过大图片压缩"压成 JPEG，动图信息会丢失（主程序在 Hook 之前处理）；
- 每条新动图会多一次视觉模型调用，首次识别有数秒延迟；缓存命中后无额外开销；
- 注入文本会进入消息的处理文本，可能被表达/黑话学习模块看到（影响很小）。

## 开发与测试

纯逻辑测试不需要启动 MaiBot（需要 Pillow 与 `maibot_sdk`）：

```bash
python -m unittest discover -s tests -v
```

测试覆盖：格式嗅探、元信息/采样/渲染、帧板输出、缓存、限流、降级、转发递归，以及按宿主方式加载 `plugin.py` 并实际调用 Hook。

## 隐私

动图帧板会像普通图片描述一样发送给主程序配置的视觉模型服务；插件不会把内容发往其它地址，也不内置任何外部 API。
